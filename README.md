# Santai Hub Status

Public status page: https://santai-inc.github.io/santai-status/

Checks the Hub website and API health endpoint using [Upptime](https://upptime.js.org/).
The API check confirms that the process responds; it does not test the database, editor, knowledge bases, or group chat.

## Operation

- Availability checks are scheduled every five minutes. GitHub Actions schedules may be delayed.
- Response-time history, uptime summaries, and graphs refresh every six hours.
- The website rebuilds hourly and after configuration or branding changes. Its client also reads monitoring data from this repository.
- Outages open public GitHub issues; recovery closes them. Maintainers can add incident updates as comments.
- Planned maintenance can be announced with the scheduled-maintenance issue template. Replace its placeholder dates before submitting.
- History begins with the first checks. The repository contains no imported Santai uptime history.

Edit `.upptimerc.yml` to change monitored endpoints or page text. Run the workflows manually from Actions when an immediate refresh is needed.

## Hosting and credentials

This public repository uses standard GitHub-hosted runners and GitHub Pages. No paid service or personal access token is required.
Each workflow uses the temporary, repository-scoped `GITHUB_TOKEN` with explicit permissions.
Pages is configured to deploy through GitHub Actions.

The three workflows are maintained here rather than regenerated by Upptime, because template regeneration requires permission to rewrite workflows and its branch-based deployment expects a separate token. Upptime is pinned to `v1.44.0`; update its version in all three workflows together.
